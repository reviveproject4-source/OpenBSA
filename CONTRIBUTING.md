# Contributing to OpenBSA

Thank you for your interest in contributing to **OpenBSA**! We welcome contributions from Business Analysts, Systems Architects, Product Managers, and Engineers worldwide.

---

## 🌟 How You Can Contribute

1. **Add New Architecture & Process Patterns:**
   * Additional Mermaid.js templates (e.g., Event Sourcing flows, Saga orchestrations, OAuth2 Grant types, Multi-region failover).
2. **Refine Existing Templates:**
   * Improve checklists, add real-world edge cases, or introduce industry-specific sections (Fintech, Healthtech, E-commerce, AI).
3. **Docs-as-Code Tooling:**
   * Add automated GitHub Actions workflows (e.g., Markdown linting, Mermaid diagram validation).

---

## 📝 Submission Guidelines

### 1. Code & Markdown Style
* Write all documentation in **Standard US English**.
* Use clean GitHub-flavored Markdown.
* For all diagrams, prefer native **Mermaid.js** blocks (```` ```mermaid ````) so they render automatically in GitHub and Markdown viewers without external image dependencies.
* Ensure all templates have placeholder instructions wrapped in bracket comments like `<!-- Explain your context here -->` or `[Insert System Name]`.

### 2. Pull Request Process
1. Fork the repo and create your branch from `main`:
   ```bash
   git checkout -b feature/add-saga-orchestration-flow
   ```
2. Make your additions or improvements with clear commit messages.
3. Verify that your Mermaid diagrams render cleanly without syntax errors.
4. Submit your Pull Request with a clear description of the problem solved and use cases covered.

---

We are committed to providing a friendly, safe, and welcoming environment for all contributors, regardless of experience level, gender identity, sexual orientation, disability, personal appearance, race, ethnicity, or religion.
